# 题库维护 / AI 导入规范

本规范用于：**让 AI（或自己）安全、可核查地往题库里加篇目**。
核心原则：AI 只负责「按规范生成数据」，网页永远静态运行，不调用任何 AI 接口。

> 网页端永远不联网调用 AI，也不允许出现 `const API_KEY = "..."` 之类的硬编码密钥。
> AI 只在「维护题库」这一环节使用：生成 / 检查 / 扩充 `data/*.js` 里的数据。

## 一、标准流程（每次新增篇目都要走一遍）

1. **查验权威来源**：先确认篇目是否属于目标体系（课标 / 统编教材 / 地区教材），拿到可追溯的出处（文件名称 + 附录编号 + 条目序号）。
2. **判断归属**：属于课标推荐、统编教材、地区教材还是拓展？不得把教材差异硬塞进「全国统一篇目」。
3. **查重**：在 `data/junior.js`、`data/senior.js` 里搜索篇名与作者。判定口径：
   `标题 + 作者 + 学段 + 正文（去空白）` 完全相同 = 重复收录（`node tools/qa-data.cjs` 会报 ERROR）；
   只是标题 + 作者相同、正文或学段不同（如初中 / 高中各自的《论语》十二章）不算重复，只需人工确认。
4. **核对正文**：以教材通行版本为准，逐字核对；全角标点；不加换行。
5. **核对元信息**：标题（含（其一）（并序）等后缀）、作者、朝代、体裁、年级。
6. **检查错别字与易混字**：重点看「祇/祗」「曾/层」「佩/珮」「唯/惟」「辩/辨」「是/斯」等。
7. **记录异文**：有版本差异时写入 `variants`，不要把两个版本混在正文里。
8. **输出标准 JSON**（见下）。
9. **本地自检**：`node tests/unit.mjs && node tools/qa-data.cjs`（数据体检会直接检查原始数组，
   重复 / 字段缺失以非 0 退出码报告）。
10. **重新打包**：`npm run build`（构建自检会比较源数据条数与打包产物条数是否精确相等）。

## 二、字段规范

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 是 | 拼音短横线，全局唯一，如 `guan-cang-hai` |
| `title` | 是 | 篇名，含后缀，如 `行路难（其一）`、`琵琶行（并序）` |
| `author` | 是 | 作者；无名氏用 `佚名`，结集作品用 `《诗经》`、`《古诗十九首》` |
| `dynasty` | 是 | 朝代，如 `唐`、`北宋`、`先秦`、`现代` |
| `stage` | 是 | `初中` 或 `高中` |
| `grade` | 是 | 初中：`六年级`…`九年级`；高中：`必修`、`选择性必修`、`选修`（课程模块，按统编教材分册归属，不写“高一/高二/高三”，也不单列“诗词曲”） |
| `grades` | 否 | 跨年级篇目填数组，如 `["八年级", "九年级"]`（值同样必须在 `metadata.grades` 里） |
| `genre` | 是 | `诗` / `词` / `曲` / `文言文` / `其他` |
| `sourceType` | 是 | `课标推荐` / `统编教材` / `上海地区` / `拓展` |
| `required` | 是 | 是否课标核心必背 |
| `recommended` | 是 | 是否推荐学习 |
| `text` | 是 | 正文，全角标点，无换行 |
| `translation` | 是 | 逐句现代汉语翻译数组，**长度必须等于 `Utils.splitSentences(text)` 的句数**，下标即句序；详见 `docs/逐句翻译维护规范.md` |
| `source` | 是 | 出处，例如 `《普通高中语文课程标准（2017年版2020年修订）》附录1 · 诗词曲第26首` |
| `notes` | 否 | 说明，例如课标指定节选范围 |
| `highlights` | 否 | 背诵提示：`{ type: '名句' \| '易错字' \| '关键词', text: '…' }` |
| `variants` | 否 | 异文：`{ label: '版本差异', text: '…' }` |
| `tags` | 否 | 标签数组，如 `['豪放','词']` |

## 三、标准 JSON 模板

```json
{
  "id": "duan-ge-xing",
  "title": "短歌行",
  "author": "曹操",
  "dynasty": "东汉",
  "stage": "高中",
  "grade": "选择性必修",
  "genre": "诗",
  "sourceType": "课标推荐",
  "required": true,
  "recommended": true,
  "text": "对酒当歌，人生几何！……周公吐哺，天下归心。",
  "translation": [
    "面对美酒应当高歌，人生短暂能有多少时光！",
    "……（与 splitSentences(text) 一一对应，逐句直译，不写赏析）"
  ],
  "source": "《普通高中语文课程标准（2017年版2020年修订）》附录1 · 诗词曲第5首",
  "notes": "",
  "highlights": [
    { "type": "名句", "text": "山不厌高，海不厌深。周公吐哺，天下归心。" },
    { "type": "易错字", "text": "子衿 呦呦 掇 契阔谈䜩" }
  ],
  "variants": []
}
```

转换成数据文件时，把 JSON 对象直接粘进 `data/senior.js` 的数组里即可（JavaScript 支持这种字面量写法）。

## 四、AI 提示词模板（可直接复制给 AI 使用）

```text
请按照《AI题库维护规范》给「上海初高古诗文背诵」新增/核对篇目。

要求：
1. 只输出符合规范的 JSON 数组，不要输出解释文字。
2. 每条数据必须包含：id、title、author、dynasty、stage、grade、genre、
   sourceType、required、recommended、text、translation、source。
3. 正文以统编教材通行版本为准，使用全角标点，不要换行，不要加入注释或译文。
   translation 是**逐句直译**：长度必须等于把 text 按 。！？… 切分后的句数，
   第 k 条译文只对应第 k 句原文；不写赏析、不合并句子、不调换顺序。
4. 如果存在教材版本差异，写入 variants，不要合并进正文。
5. 年级 / 课程模块只能从 `data/metadata.js` 的 `grades` 里取值：
   初中用「六年级…九年级」，高中用「必修 / 选择性必修 / 选修」
   （统编必修上/下 → 必修，选择性必修上/中/下 → 选择性必修，教材未收录的课标篇目 → 选修）；
   跨年级篇目（如《孟子》三则分属八年级、九年级）额外加 `grades` 数组，
   并在 notes 里说明依据；不要写「七~九年级」「初中」「高一」这类旧值。
6. 先查重：不要重复收录已有篇目。

本次任务：核对并补全「高中 选择性必修」全部篇目。
```

## 五、常见错误清单（提交前对照检查）

- [ ] `id` 与已有篇目重复
- [ ] 篇名缺少「（其一）」「（并序）」「·」等后缀，导致与其他篇目混淆
- [ ] 作者写作「宋•辛弃疾」这种混合写法（本项目作者与朝代分字段填写）
- [ ] 正文里混入半角标点（`,` `.` `?` `!`）或空格
- [ ] 正文里手动换行（本项目由程序自动切分句子）
- [ ] 把译文、注释、鉴赏混进 `text`
- [ ] `translation` 条数与正文句数不一致（会导致逐句翻译错位 / 缺翻译）
- [ ] `translation` 写成整首串讲、赏析，或与原文完全相同（等于漏译）
- [ ] 课标节选篇目录了全文（例如《离骚》《报任安书》只录课标指定范围）
- [ ] 异文未写入 `variants`，直接与教材版本混排
- [ ] `sourceType` 用错（把教材篇目写成课标推荐）
- [ ] 改动后忘记 `npm run build`

## 六、纠错

发现错别字 / 标点问题：直接改 `data/` 下对应数据文件，运行 `node tests/unit.mjs`，
再 `npm run build`。改动越小越好，避免顺带重构无关内容。

改了 `text` 就必须同步 `translation`（句数可能变化）：按 `docs/逐句翻译维护规范.md`
里的流程重跑 `tools/translations/` 下的脚本。
