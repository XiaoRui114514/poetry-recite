# 逐句翻译维护说明

本目录存放「全文学习」页每一句原文对应的现代汉语翻译，以及生成 / 校验 / 写回题库的工具。

## 一、数据流

```
tools/translations/make-batches.cjs   →  data/translations/in/batch-NN.json      （按 Utils.splitSentences 切好的原文句子清单）
                                        ↓ 人工 / AI 逐句翻译
                                      data/translations/poems/batch-NN.json     （译文，与 in/ 的句子下标一一对应）
tools/translations/verify.cjs         →  校验批次译文（篇数、句数、空值、占位符）
tools/translations/inject.cjs         →  把译文写回 data/junior.js、data/senior.js 的 translation 字段
```

- `in/` 与 `poems/` 的**篇目顺序与句子顺序完全一致**：`poems/batch-NN.json` 里
  `poems[k].translations[i]` 就是 `in/batch-NN.json` 里 `poems[k].sentences[i]` 的翻译。
- 想核对某一句，直接并排打开这两个文件即可，不需要做任何字符串匹配。

## 二、字段约定

题库里每个篇目新增一个字段：

```js
{
  id: 'guan-ju',
  text: '关关雎鸠，在河之洲。……',
  translation: [
    '雎鸠鸟关关地叫着，停在河中的小洲上。',
    // ……与 Utils.splitSentences(text) 一一对应，长度必须完全相等
  ],
}
```

- 数据库层（`data/database.js`）把它整理成 `poem.translations`（数组），
  并提供 `PoetryDatabase.translationLines(poem)`：返回与 `Utils.splitSentences(poem.text)`
  **下标严格对齐**的译文数组，缺翻译的位置补空字符串。
- 页面（`js/study.js`）只按 index 取用，**不做任何字符串搜索匹配**，
  因此不会因为标点、换行、异文导致翻译错位。

## 三、常用命令

```bash
# 1) 重新按题库正文切句，生成可核查的原文清单（会覆盖 in/）
node tools/translations/make-batches.cjs 170

# 2) 校验译文与原文的对应关系（篇数 / 句数 / 空值 / 占位符 / 与原文雷同）
node tools/translations/verify.cjs

# 3) 按现有 poems/ 的篇目顺序重建 in/（改了题库正文后用它对齐）
node tools/translations/rebuild-input.cjs

# 4) 把译文写回题库（幂等，可反复执行；写盘前会用 vm 真的跑一遍产物）
node tools/translations/inject.cjs --check   # 只检查不写盘
node tools/translations/inject.cjs           # 正式写入
```

改完题库后必须回到仓库根目录执行：

```bash
npm run test:data && npm run test:unit && npm run build
```

## 四、硬性约束（`tools/qa-data.cjs` 与 `tests/unit.mjs` 会自动检查）

1. 每篇必须有 `translation` 数组，且 `translation.length === Utils.splitSentences(text).length`。
2. 每条译文非空，不含换行 / 制表符 / `□` 占位符。
3. 译文不得与原文完全相同（说明漏译了）。
4. 不允许出现「一句原文对应两句翻译」或顺序错位——长度相等 + 下标对齐即可保证。

## 五、页面交互约定（`js/study.js`）

翻译属于「这一句」的附属内容，显示条件只有一个：

> **翻译可见 ⟺ 该句原文处于“完整显示”状态**（`!state.hidden[index]`）

对应关系如下（`tests/e2e.spec.mjs` 与 `tests/responsive.spec.mjs` 会实测）：

| 操作 | 原文 | 翻译 |
| --- | --- | --- |
| 显示全部 | 完整显示 | 显示 |
| 点击某句（隐藏 / 恢复） | 挖空 / 恢复 | 同步隐藏 / 恢复 |
| 逐句隐藏 | 全部挖空 | 全部隐藏 |
| 关键词隐藏 | 全部关键词挖空 | 全部隐藏 |
| 上一句 / 下一句 | 当前句高亮 | 跟随该句状态 |

**不要**给翻译单独加开关或顶部按钮。翻译的显隐由这一条规则唯一决定。

### 为什么不跳动

1. `.line-zh` **始终留在 DOM 里**，隐藏时只切 `.is-off`（CSS `visibility: hidden`），
   不用 `display: none`，所以行盒高度和整首诗的高度都不变；
2. `.line-zh` 还有 `min-height: 1.6em`，翻译文本被清空 / 换行数变化时高度也不变；
3. 点击交互走 `updateLines()` **原位更新**（只改 `textContent` 与 class），
   不再对 `#poemBody` 做 `innerHTML` 重建，所以文档高度、滚动位置、当前句位置都不会漂移。
   `refreshBody()`（整块重建）只在首次渲染与切换篇目时使用。

如果要改这里的实现，请保留这三条，并跑 `npx playwright test -g 逐句翻译` 验证
`#poemBody` 高度与文档总高度在隐藏 / 显示前后完全一致。

## 六、正文里带 `【】` 分则的篇目

《孟子》三则、《老子》八章、《古代文论选段》等篇目正文用 `【小标题】` 分则，
而 `Utils.splitSentences()` 只在 `。！？…` 与换行处切句，所以：

- 这些小标题会留在所在句子里，翻译时按「小标题 + 该则内容」整体翻译；
- **不要**为了好看往正文里塞换行或删掉 `【】`，否则句子数量会变、译文全部错位。

《论语》十二章（初中）是唯一一处需要按「章」逐句排列的长文：
正文用 `\n` 分成 12 行（每章一行），这样 `splitSentences()` 的结果与课标「十二章」一一对应，
页面上每一章单独成行、各自有翻译。
