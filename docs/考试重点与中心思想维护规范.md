# 考试重点与中心思想维护规范

本文说明全文学习页「考试重点 ★」与「中心思想 / 主旨」两项数据的来源、字段约定、判定标准与维护命令。

## 一、数据在哪里

两项都属于**文章级 / 句子级元数据**，存在题库原始数据层（`data/junior.js`、`data/senior.js`），与正文 `text` 完全分离：

```js
{
  id: 'yue-yang-lou-ji',
  title: '岳阳楼记',
  text: '庆历四年春，滕子京谪守巴陵郡。……',   // 正文，绝不包含 ★
  translation: [ ... ],                       // 逐句翻译，见《逐句翻译维护规范》
  summary: '本文叙写岳阳楼重修一事，描绘洞庭湖的雄伟景象……',   // 中心思想 / 主旨
  examFocus: [                                // 考试重点句，只存句子下标
    { index: 15, reason: '名句，体现旷达胸襟' },
    { index: 18, reason: '主旨句，名句，默写常考' },
  ],
}
```

| 字段 | 层级 | 说明 |
| --- | --- | --- |
| `summary` | 原始数据层 | 中心思想 / 主旨，40～110 字，一句话到三句话 |
| `examFocus` | 原始数据层 | `[{ index, reason }]`；`index` = `Utils.splitSentences(text)` 的下标（从 0 开始） |
| `poem.summary` | 数据库层 | 同 `summary`，已 trim |
| `poem.examFocus` | 数据库层 | 已过滤掉缺 `index` 的坏数据 |
| `PoetryDatabase.examFocusMap(poem)` | 数据库层 | 返回 `{ 句子下标: { reason } }`，**丢弃越界下标**，页面据此决定 marker 里有没有 ★ |

> `reason` 是**内部维护依据，不在界面上显示**。界面上只有一个 `★`。

## 二、硬性约束

1. **`★` 绝不进入 `text`。** 正文、标题里出现 `★` / `☆` 会被 `qa-data` 与 `unit` 判为 ERROR。
   星标只由独立的 `.line-marker` 元素渲染。这样搜索、默写、判分、复制、数据校验都不受影响。
2. **marker 与正文是两个独立元素。** DOM 结构为
   `button.line-item > span.line-marker + span.line-content > (span.line-text + span.line-zh)`。
3. **marker 列宽固定。** `grid-template-columns: 1.25em 1fr`，有没有 ★ 都占位；
   隐藏只切 `visibility`（**不要用 `display: none`**，那会让原文左移）。
4. **`index` 必须是正文句数范围内的整数，且同一篇内不重复。** 越界会在数据库层被静默丢弃
   （页面不会崩），但 `qa-data` / `unit` 会判为 ERROR。
5. **`reason` 只写可核查的依据类型**，不允许出现年份、「中考真题」「高考真题」「一模」「二模」「高频」
   等无法核查的考试频率表述（`qa-data` 会对这些字样报 ERROR）。

## 三、页面交互约定（`js/study.js`）

星标的显示条件与译文完全一致：

> **星标可见 ⟺ 该句原文处于「完整显示」状态**（`!state.hidden[index]`）

| 操作 | 原文 | ★ | 译文 |
| --- | --- | --- | --- |
| 显示全部 | 完整显示 | 显示 | 显示 |
| 点击某句（隐藏 / 恢复） | 挖空 / 恢复 | 同步隐藏 / 恢复 | 同步隐藏 / 恢复 |
| 逐句隐藏 | 全部挖空 | 全部隐藏（占位保留） | 全部隐藏 |
| 关键词隐藏 | 关键词挖空 | **必须一起隐藏**（不能出现「★ 先□□」） | 全部隐藏 |
| 上一句 / 下一句 | 当前句高亮 | 跟随该句状态 | 跟随该句状态 |

**不要**给星标单独加开关或顶部按钮。星标与译文的显隐都不做 DOM 重建：
点击交互走 `updateLines()` 原位更新（只改 `textContent` 与 class），
所以文档高度、滚动位置、当前句位置都不会漂移。

## 四、考试重点怎么判（依据类型）

判定依据只能来自下面几类**可核查的事实**：

| 代号 | 依据 | 说明 |
| --- | --- | --- |
| A | 主旨句 / 中心句 | 直接表达全文主旨或作者核心观点、情感、志向的那一句 |
| B | 纲领句 / 关键论断句 | 文章论点、结论，或人物最关键的一句话 |
| C | 名句 / 千古流传句 | 历来被公认为该篇代表句的句子 |
| D | 默写常考句 | 结构工整、意象典型，常用于名句填空 / 理解性默写 |
| E | 含重要文言知识 | 通假字、古今异义、词类活用、特殊句式密集，常被用来出翻译题 |
| F | 易错字密集 | 句中有容易写错的字 |

**数量：少而精。** 短绝句 / 小令 2～3 句；中等篇幅 3～4 句；长篇文言文 4～6 句；
篇幅特别长且考点确实多的（《琵琶行》《滕王阁序》《逍遥游》）最多 6～8 句。
**不要**标纯叙事过渡句、纯写景铺陈句、单纯问答口气句。

## 五、中心思想怎么写

- 每篇必填，40～110 字，1～3 句话。
- 写清「**写了什么 + 表现 / 表达 / 揭示了什么**」。
- 文言文写「中心思想」：主要写了什么事 / 论述了什么道理 + 作者的观点态度或写作意图。
- 诗词写「主旨 / 思想感情」：内容概括 + 诗人情感（或志向、情趣、哲理）。
- 用现代汉语，平实准确，适合初高中学生读。
- **不要**写作者生平、写作背景、手法术语堆砌、分段解析。
- **不要**把有争议的文学评论观点写进去；采用通行教材 / 课标的主流解释。
- 界面上：文言文显示标题「中心思想」，其他体裁显示「主旨」（见 `summaryLabel()`）。

## 六、维护命令

```bash
# 1. 从题库导出待填清单（默认保留已填内容；--rebuild 以题库现有值为准）
node tools/meta/export.cjs                        # → meta/poems.json
node tools/meta/export.cjs --split --batch 12     # 另外拆成 meta/batches/batch-NN.json
node tools/meta/export.cjs --rebuild --split --batch 12   # 直接改过题库后，用它把维护文件同步回最新

# 2. 填好后写回题库（幂等，可反复执行；写盘前用 vm 真跑一遍校验）
node tools/meta/inject-meta.cjs --dry      # 只看会写什么
node tools/meta/inject-meta.cjs            # 正式写入
node tools/meta/inject-meta.cjs --check    # 只检查，不写
node tools/meta/inject-meta.cjs --allow-empty   # 只注入已填写的篇目（分批维护用）

# 3. 体检与测试
node tools/qa-data.cjs                     # 字段 / 下标 / 重复 / 正文含 ★ / summary
node tests/unit.mjs                        # 单元检查
npm run build                              # 打包单文件版
npx playwright test -g "考试重点|中心思想"  # 端到端
```

`meta/` 是**中间产物目录**：`meta/poems.json` 是唯一需要入库的维护文件（可读可改、便于 review）；
`meta/batches/` 只是由它拆分出来的分批文件，已加入 `.gitignore`，随时可以用
`node tools/meta/export.cjs --split --batch 12` 重新生成。
`inject-meta.cjs` 每次先剥掉已有 `summary` / `examFocus` 字段再重新插入，
因此可以反复执行且结果稳定（幂等）。

> **注意**：如果直接手改了 `data/*.js` 里的 `summary` / `examFocus`，
> 记得跑一次 `node tools/meta/export.cjs --rebuild --split --batch 12`
> 把 `meta/` 同步回最新，否则下次运行 `inject-meta.cjs` 会用手改前的旧值覆盖你的修改。

## 七、修改正文之后必须做的事

`examFocus.index` 依赖 `Utils.splitSentences(text)` 的切分结果。
**只要改了 `text`（增删字、改标点、改换行），就必须重新核对 `examFocus` 的下标**，
并重跑 `node tools/qa-data.cjs`；`translation` 同理。

## 八、数据来源与诚实边界

- 篇目范围、`required` / `sourceType` 等以**教育部课程标准官方文件**与**现行统编（部编）教材**为准。
- 「考试重点」的判定依据是**公开可核查的教学事实**：课标背诵推荐篇目、教材与教师用书对
  主旨句 / 名句 / 重点实词虚词的普遍要求、以及古诗文默写与翻译题长期稳定的考查惯例。
- **本项目不掌握、也不声称掌握任何上海中考 / 高考的逐句考试频率统计**，
  因此 `reason` 里一律不写「某年考过」「高频」这类无法核查的表述；
  `qa-data` 会对这类字样直接报 ERROR。
- 如果某篇找不到足够可靠的依据，**宁可标得保守**（少标一两句），也不要为了看起来完整而编造。
- 正式加入题库前必须人工核对。古诗文错一个字，背诵就可能白背。
